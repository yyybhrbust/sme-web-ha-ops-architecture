# 毕业设计实现方案（RHEL 10 版）

> 题目：《基于开源技术栈的中小企业 Web 业务高可用运维架构设计与实现》
> 环境：VMware Workstation 17.6.2（本机 `D:\Virtual Machines`），源镜像 **Red Hat Enterprise Linux 10**（`Red Hat Enterprise Linux 10 64 位.vmx`），NAT 网段 **192.168.10.0/24**。宿主机虚拟网卡为 192.168.10.1，**NAT 设备（虚拟机默认网关）为 192.168.10.2**。
> 本文档把对话里的毕设方案落成可执行步骤，命令均按 RHEL 10（dnf / firewalld / SELinux / nmcli）编写，并标注与 CentOS 版的差异。方括号 `[...]` 为执行时需按实际填入的值。

---

## 一、总体架构与 IP 规划

```
                     [Internet / 宿主机 192.168.10.1]
                                  |
                          VIP: 192.168.10.100
                    +--------------+--------------+
                    |                             |
            LB-Master(MASTER)             LB-Backup(BACKUP)
             192.168.10.10                 192.168.10.20
              Nginx+Keepalived              Nginx+Keepalived
                    |          \           /          |
                    |           \         /           |
                  Web1 192.168.10.101  Web2 192.168.10.102(可选)
                    |      Nginx+PHP+MariaDB(业务DB)  |
                    |                |                |
              Zabbix Server 192.168.10.200 (Zabbix+MariaDB+Web)
```

| 主机名 | IP（静态） | 角色 | 安装软件 | 防火墙放行 |
| :--- | :--- | :--- | :--- | :--- |
| lb-master | 192.168.10.10 | 主负载均衡器 | nginx、keepalived(MASTER)、zabbix-agent2 | 80、10050、VRRP |
| lb-backup | 192.168.10.20 | 备负载均衡器 | nginx、keepalived(BACKUP)、zabbix-agent2 | 80、10050、VRRP |
| web1 | 192.168.10.101 | 业务服务器 | nginx、php-fpm、mariadb(业务库)、zabbix-agent2 | 80、10050 |
| web2（可选） | 192.168.10.102 | 业务服务器2 | 同 web1（克隆） | 80、10050 |
| zabbix | 192.168.10.200 | 监控中心 | mariadb、zabbix-server、zabbix-web、zabbix-agent2 | 80、10050、10051 |
| VIP | 192.168.10.100 | 虚拟 IP | 由 Keepalived 生成，不绑物理网卡 | — |

> 说明：对话原方案为 4 台（LB×2 + Web1 + Zabbix），本方案按此落地；Web2 为可选项，验证负载均衡/加权时再克隆。业务数据库初期放在 Web1 上（简化拓扑），毕设报告中注明"生产环境 DB 独立部署"。

## 二、阶段零：克隆红帽虚拟机（4 台）

源虚拟机必须处于**关机**状态（当前未运行，满足条件）。用 vmrun 做完整克隆：

```powershell
# 在宿主机 PowerShell 执行（vmrun 路径：D:\Program Files (x86)\VMware\VMware Workstation\vmrun.exe）
$vmrun = 'D:\Program Files (x86)\VMware\VMware Workstation\vmrun.exe'
$src   = 'D:\Virtual Machines\RHEL10\Red Hat Enterprise Linux 10 64 位.vmx'
& $vmrun clone $src 'D:\Virtual Machines\LB-Master\LB-Master.vmx' linked
& $vmrun clone $src 'D:\Virtual Machines\LB-Backup\LB-Backup.vmx' linked
& $vmrun clone $src 'D:\Virtual Machines\Web1\Web1.vmx' linked
& $vmrun clone $src 'D:\Virtual Machines\Zabbix\Zabbix.vmx' linked
```

> 本机 D 盘空间紧张（12GB 空闲），实际采用 **linked 链接克隆**（增量盘仅几 MB 起，随安装增长约 2-4GB/台）；若空间充足可用 full 完整克隆（每台约 25GB）。

克隆后注意：
1. 每个克隆的 `.vmx` 会自动生成新 MAC 地址，网卡互不冲突。
2. 如克隆报"源被锁定"，先删除源目录残留的 `*.lck` 目录（确认虚拟机未运行）。
3. 源 VM 的 `.vmx` 为 GBK 编码：如需用脚本改 memsize/displayName，必须按 GBK 写回（UTF-8 BOM 会导致 VMware 无法读取配置）。
4. 依次启动克隆并设置主机名/IP（见阶段一）。启动命令：`& $vmrun start 'D:\Virtual Machines\LB-Master\LB-Master.vmx' nogui`。
5. **克隆机必须重新注册红帽订阅**：克隆继承源镜像的注册状态，但注册单元在红帽服务器端已被删除（HTTP 410 Gone），仓库报 403。每台克隆需先 `subscription-manager unregister` 再 `subscription-manager register --username 账号 --password 密码`；RHEL 10 已移除 `--auto-attach` 选项，org 开启 Simple Content Access 时注册后仓库自动启用。
6. 源镜像残留不可达的 `nodesource-nodejs/nodesource-nsolid` 仓库会拖垮 dnf，先禁用：`sed -i 's/^enabled=1/enabled=0/' /etc/yum.repos.d/nodesource*.repo`。

## 三、阶段一：每台 VM 的基础环境配置（RHEL 10）

以下命令在**每一台虚拟机内**执行（用 SSH 或控制台），仅 IP/主机名不同。

### 1. 检查 RHEL 订阅（决定能否装软件包）

```bash
subscription-manager status        # 查看订阅状态
dnf repolist                       # 看 BaseOS/AppStream 是否可用
```

- 若显示未注册/无有效订阅：需要注册（免费开发者订阅）。RHEL 10 命令：`subscription-manager register --username 你的账号 --password 你的密码`（**`--auto-attach` 已移除**；若 org 未开启 SCA 再执行 `subscription-manager attach --auto`）。这一步直接决定 `dnf install` 能否成功，**注册后**再继续。
- 若显示已注册但 dnf 报 403：注册单元已被服务器端删除（`subscription-manager refresh` 报 410 Gone），需 `subscription-manager unregister` 后重新注册（本机四台克隆均如此处理）。
- 若 dnf 卡在不可达仓库：先禁用 nodesource 等残留仓库（见阶段零注意 6）。

### 2. 设置主机名与静态 IP

```bash
# 主机名（各自不同）
hostnamectl set-hostname lb-master.example.com   # lb-backup / web1 / zabbix 同理

# 查看网卡名（RHEL 10 通常为 ens160）
ip -o link show | awk -F': ' '{print $2}'

# 设置静态 IP（以 lb-master 为例；其余按 IP 规划表改）
nmcli con mod ens160 \
  ipv4.method manual \
  ipv4.addresses 192.168.10.10/24 \
  ipv4.gateway 192.168.10.2 \
  ipv4.dns "192.168.10.2 114.114.114.114"
nmcli con up ens160
ip addr show ens160 | grep 'inet '
```

> 连接名不一定是 "ens160"，用 `nmcli con show` 确认后再改。**注意**：`nmcli con up` 应用新 IP 后 SSH 连接会中断，属正常现象（原 IP 失效），重新连新 IP 即可。

### 3. SELinux 设为 permissive（毕设环境）

```bash
setenforce 0
sed -i 's/^SELINUX=.*/SELINUX=permissive/' /etc/selinux/config
getenforce    # 输出 Permissive
```

> 报告写法：毕设环境为规避 SELinux 端口/文件上下文配置的复杂性采用 permissive；生产环境应 enforcing，并在报告中列出需要放行的 SELinux 布尔值与端口（如 `semanage port -a -t zabbix_port_t -p tcp 10050` 等）。

### 4. firewalld 放行端口（保持防火墙开启，体现工程规范）

```bash
systemctl enable --now firewalld
# 通用：HTTP + Zabbix agent + VRRP
firewall-cmd --permanent --add-service=http
firewall-cmd --permanent --add-port=10050/tcp
firewall-cmd --permanent --add-rich-rule='rule protocol value="vrrp" accept'
# 仅 Zabbix 服务器额外放行 10051（server 收 agent 主动数据）
#   firewall-cmd --permanent --add-port=10051/tcp
firewall-cmd --reload
firewall-cmd --list-all
```

### 5. 时间同步与基础软件

```bash
timedatectl set-timezone Asia/Shanghai
dnf install -y chrony vim wget tar rsync net-tools cronie   # cronie 提供 crontab 定时任务
systemctl enable --now chronyd crond
timedatectl set-ntp true
```

## 五、阶段三：负载均衡与高可用（LB-Master / LB-Backup）

### 1. 安装

```bash
dnf install -y nginx keepalived
```

### 2. Nginx 反向代理/负载均衡（两台 LB 配置相同）

编辑 `/etc/nginx/nginx.conf`，在 `http {}` 内替换 server 段：

```nginx
upstream backend_servers {
    server 192.168.10.101:80 weight=1;   # Web1
    server 192.168.10.102:80 weight=1;   # Web2（可选，未部署可先注释）
}
server {
    listen 80;
    server_name 192.168.10.100;
    location / {
        proxy_pass http://backend_servers;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

```bash
nginx -t && systemctl enable --now nginx
```

### 3. Keepalived 主备配置

**LB-Master** `/etc/keepalived/keepalived.conf`：

```bash
global_defs {
   router_id LB_MASTER
}
vrrp_instance VI_1 {
    state MASTER
    interface ens160            # 用 ip addr 确认实际网卡名
    virtual_router_id 51
    priority 100
    advert_int 1
    authentication {
        auth_type PASS
        auth_pass 1111
    }
    virtual_ipaddress {
        192.168.10.100/24
    }
}
```

**LB-Backup** 同文件，改三处：`router_id LB_BACKUP`、`state BACKUP`、`priority 90`。

```bash
systemctl enable --now keepalived
# 验证
ip addr show ens160 | grep 192.168.10.100   # Master 上应出现 VIP
curl http://192.168.10.100/                 # 经 VIP 访问到后端页面
```

### 4. 高可用故障切换验证（毕设核心亮点）

```bash
# 在 LB-Master 上执行
systemctl stop keepalived
# 立刻在 LB-Backup 上执行
ip addr show ens160 | grep 192.168.10.100   # VIP 已漂移过来
curl http://192.168.10.100/                 # 业务仍可访问
```

记录切换耗时（`advert_int 1` 时约 1-3 秒内完成），截图对比切换前后两台机器的 `ip addr` 输出。

## 六、阶段四：监控中心 Zabbix（Zabbix 服务器 192.168.10.200）

### 1. 安装 Zabbix 官方仓库（RHEL 10 实测使用 **Zabbix 7.0 LTS**，7.4 尚无 el10 源）

```bash
rpm -Uvh https://repo.zabbix.com/zabbix/7.0/rhel/10/x86_64/zabbix-release-latest.el10.noarch.rpm
dnf clean all
dnf install -y zabbix-server-mysql zabbix-web-mysql zabbix-nginx-conf zabbix-agent2 mariadb-server
```

> 实测：`repo.zabbix.com/zabbix/7.0/rhel/10/x86_64/` 已有全套 el10 包（zabbix-server-mysql / zabbix-web-mysql / zabbix-nginx-conf / zabbix-agent2 等，7.0.30）；7.4 目录不存在。Zabbix 7.x 前端默认走 nginx+php-fpm（不再用 httpd）。

### 2. 初始化数据库

```bash
systemctl enable --now mariadb
mysql <<'EOF'
create database zabbix character set utf8mb4 collate utf8mb4_bin;
create user 'zabbix'@'localhost' identified by 'Zabbix@2026';
grant all privileges on zabbix.* to 'zabbix'@'localhost';
EOF
zcat /usr/share/zabbix-sql-scripts/mysql/server.sql.gz | mysql --default-character-set=utf8mb4 -uzabbix -p'Zabbix@2026' zabbix
```

### 3. 配置 server 与前端（Zabbix 7.x 用 nginx+php-fpm，不再用 httpd）

```bash
sed -i "s/^# DBPassword=.*/DBPassword=Zabbix@2026/" /etc/zabbix/zabbix_server.conf

# 前端：编辑 /etc/nginx/conf.d/zabbix.conf（zabbix-nginx-conf 已生成骨架）
#   改 listen 80; server_name zabbix;（骨架内默认 8080，需改 80）
vim /etc/nginx/conf.d/zabbix.conf

systemctl enable --now zabbix-server zabbix-agent2 php-fpm nginx
```

浏览器访问 `http://192.168.10.200/zabbix`，默认账号 **Admin / zabbix**（首次登录提示改密码，按向导下一步即可）。

### 4. 接入被监控主机（Web1、LB-Master、LB-Backup 装 agent）

```bash
# 在 web1 / lb-master / lb-backup 上
rpm -Uvh https://repo.zabbix.com/zabbix/7.0/rhel/10/x86_64/zabbix-release-latest.el10.noarch.rpm
dnf clean all && dnf install -y zabbix-agent2

# 编辑 /etc/zabbix/zabbix_agent2.conf
#   Server=192.168.10.200
#   ServerActive=192.168.10.200
#   Hostname=web1   （与 Zabbix 前端添加的主机名一致）
systemctl enable --now zabbix-agent2
```

Zabbix 前端 → 数据采集 → 主机 → 创建主机（IP 填各机、模板选 `Linux by Zabbix agent`），状态变绿色即接入成功。

### 5. 自定义监控项 + 告警（毕设亮点：故障主动发现）

**自定义监控项**（监控 Nginx 80 端口存活，web1 上）：

```bash
echo 'UserParameter=nginx.status,ss -tln | grep -c ":80 "' > /etc/zabbix/zabbix_agent2.d/nginx.conf
systemctl restart zabbix-agent2
```

前端创建监控项：键值 `nginx.status`；创建触发器：`nginx.status.last()=0` → 严重告警（"Nginx 服务宕机"）。

**告警媒介（企业微信机器人）**：

```bash
# Zabbix 服务器上写告警脚本
cat > /usr/lib/zabbix/alertscripts/wechat.sh <<'EOF'
#!/bin/bash
# $1=收件人(企业微信机器人webhook) $2=主题 $3=消息
curl -s -H 'Content-Type: application/json' \
  -d "{\"msgtype\":\"text\",\"text\":{\"content\":\"[$2] $3\"}}" \
  "$1" > /dev/null
EOF
chmod +x /usr/lib/zabbix/alertscripts/wechat.sh
```

前端：报警媒介类型 → 创建（类型 Script，脚本名 wechat.sh，参数填 3 个）；用户 Admin 添加该媒介（webhook 地址）；动作 → 创建（触发条件选"CPU load 大于 5"或"nginx.status=0"），发送给 Admin。

**验证告警链路**：`dd if=/dev/zero of=/dev/null &` 拉高 CPU → 观察 Zabbix 仪表盘 CPU 曲线陡增 → 收到微信告警通知。

## 七、阶段五：自动化备份与灾难恢复（Web1 主执行）

### 1. 备份脚本 `/scripts/backup.sh`（Web1 上）

```bash
mkdir -p /backup /scripts
cat > /scripts/backup.sh <<'EOF'
#!/bin/bash
DATE=$(date +%Y%m%d-%H%M)
# 1) 打包网站目录
tar -czf /backup/web_$DATE.tar.gz /usr/share/nginx/html
# 2) 备份业务数据库
mysqldump -uapp -p'App@2026' appdb > /backup/appdb_$DATE.sql
# 3) 清理 7 天前备份
find /backup -name 'web_*' -mtime +7 -delete
find /backup -name 'appdb_*' -mtime +7 -delete
# 4) 同步到远程备份机（LB-Master，免密需先配 SSH 密钥）
rsync -avz --delete /backup/ root@192.168.10.10:/backup/ >> /var/log/backup.log 2>&1
echo "[$(date)] backup done" >> /var/log/backup.log
EOF
chmod +x /scripts/backup.sh
```

SSH 免密（web1 → lb-master）：

```bash
ssh-keygen -t ed25519 -N '' -f /root/.ssh/id_ed25519
ssh-copy-id root@192.168.10.10
```

LB-Master 上创建备份目录：`mkdir -p /backup`。

### 2. 定时任务

```bash
crontab -e
# 每日凌晨 2 点执行
0 2 * * * /bin/bash /scripts/backup.sh > /dev/null 2>&1
```

手动跑一次验证：`bash /scripts/backup.sh && ls -lh /backup/`，并到 LB-Master 上 `ls /backup/` 确认同步成功。

### 3. 日志切割（防磁盘爆满）

nginx 日志 RHEL 包默认由 logrotate 管理（`/etc/logrotate.d/nginx`）；如业务有自定义日志，追加配置：

```bash
cat > /etc/logrotate.d/applog <<'EOF'
/var/log/app/*.log {
    daily
    rotate 7
    compress
    missingok
    notifempty
}
EOF
```

### 4. 灾难恢复演练（面试最加分项）

```bash
# 模拟故障：删除网站页面
rm -rf /usr/share/nginx/html/*
curl -I http://192.168.10.101/      # 应 404/失败

# 执行恢复（从最新备份解压）
tar -xzf /backup/web_$(ls /backup | grep '^web_' | tail -1 | sed 's/web_//;s/.tar.gz//').tar.gz -C /
# 等价写法：
LATEST=$(ls -t /backup/web_*.tar.gz | head -1)
tar -xzf "$LATEST" -C /
curl -I http://192.168.10.101/      # 恢复成功，页面 200
```

把"故障前 → 删除 → 恢复 → 恢复后"的对比截图存进毕设报告。

## 九、与 CentOS 版方案的差异对照表

| 项目 | CentOS 7 原方案 | RHEL 10 本方案 | 说明 |
| :--- | :--- | :--- | :--- |
| 包管理 | yum | dnf（yum 为兼容别名） | 命令基本一致 |
| 软件源 | 免费公开源 | 需订阅（免费开发者订阅可注册） | `subscription-manager register` |
| 防火墙 | 建议关闭 | 保持开启 + 精确放行 | 更符合工程规范 |
| SELinux | 关闭 | permissive | 规避端口/上下文配置坑，报告说明生产应 enforcing |
| Zabbix 版本 | 5.0 LTS + httpd | 7.4 LTS + nginx/php-fpm | 初始化脚本路径改为 `zabbix-sql-scripts/mysql/server.sql.gz`；默认 agent2 |
| 网卡命名 | eth0 | ens160 | 用 `ip addr` 确认 |
| 服务管理 | systemctl | systemctl | 一致 |

## 十一、常见问题排查（RHEL 10 实测）

### 1. `subscription-manager` 仓库返回 403/410

- 现象：`dnf` 报 `Status code: 403 for https://cdn.redhat.com/...`，无法安装软件
- 原因：开发者订阅的 CDN 授权令牌过期或换机后未重新注册
- 解决：每台机器执行 `subscription-manager unregister` 后 `subscription-manager register --username <账号> --password <密码>`；RHEL 10 没有 `--auto-attach`，注册后 Simple Content Access 自动启用仓库

### 2. `plink` 内联命令引号解析错误

- 现象：`bash: ... syntax error`、`$` 被 PowerShell 吞掉
- 解决：把命令写成 `.sh` 脚本用 `pscp` 上传再执行，避免多层引号

### 3. NAT 网关填成 192.168.10.1 导致不通外网

- 现象：虚拟机只能互 ping，无法访问外网/dnf
- 解决：VMware NAT 网关地址是 `192.168.10.2`，`192.168.10.1` 是宿主机虚拟网卡

### 4. rsync 备份报 `Host key verification failed`

- 现象：`/var/log/backup.log` 中 rsync 失败（exit 255）
- 原因：web1 的 `known_hosts` 没有备份机 lb-master 的主机密钥
- 解决：`backup.sh` 首次执行时 `ssh-keyscan -t ed25519 192.168.10.10 >> /root/.ssh/known_hosts`

### 5. Zabbix Agent 采集不到数据（主机"不可用"）

- 现象：仪表盘告警 "Zabbix agent is not available"，`agent.ping` 的 `lastclock=0`
- 原因：`/etc/zabbix/zabbix_agent2.conf` 仍是默认 `Server=127.0.0.1`、`Hostname=Zabbix server`，被动检查被拒绝
- 解决：`Server=192.168.10.200`、`ServerActive=192.168.10.200`、`Hostname=<本机名>`，然后 `systemctl restart zabbix-agent2`

### 6. nginx 模板页面返回 404

- 原因：默认 `server` 块 `listen 80` 被注释，未配置 `index index.html`
- 解决：`listen 80 default_server;` + `index index.html;`，并放行 firewalld 的 http

### 7. VIP 停止 keepalived 后几秒才消失

- 现象：`systemctl stop keepalived` 后 VIP 不会立刻消失
- 原因：VRRP 通告超时（约 3×advert_int）+ 漂移脚本执行时间
- 正常：5 秒内完成切换即符合设计预期

### 8. 压测出现连接重置

- 原因：VMware 单机内存受限（宿主机仅数 GB 可用），Nginx 上游含未部署节点也会加重回源失败
- 解决：关闭无关虚拟机、移除未部署的上游节点，50 并发内结果稳定
