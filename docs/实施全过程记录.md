## 第 0 阶段：环境勘察与方案定夺

### 0.1 勘察 VMware 与虚拟机资产

**操作：**
```powershell
# 查找 VMware 安装位置与 vmrun
Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\*' |
  Where-Object { $_.DisplayName -match 'VMware' } | Select DisplayName, DisplayVersion

# 读取默认虚拟机目录
Get-Content "$env:APPDATA\VMware\preferences.ini" | Select-String 'defaultVMPath'

# 列出虚拟机与硬件配置
Get-ChildItem 'D:\Virtual Machines' -Directory
Get-Content 'D:\Virtual Machines\RHEL10\Red Hat Enterprise Linux 10 64 位.vmx' |
  Select-String 'memsize|numvcpus|ethernet0|firmware'
```

**实际结果：**
- VMware Workstation 17.6.2，装在 `D:\Program Files (x86)\VMware\VMware Workstation`
- 虚拟机目录 `D:\Virtual Machines`，内有 KKali / RHEL10 / Windows 10
- RHEL10：4 vCPU、2GB 内存、NAT 网卡（vmxnet3）、EFI、约 25GB 磁盘
- 关键工具 `vmrun.exe` 路径：`D:\Program Files (x86)\VMware\VMware Workstation\vmrun.exe`

**⚠️ 阻碍 1：沙箱限制**
起初文件/网络访问受限：`Get-CimInstance`、`Get-Volume`、`systeminfo`、`nslookup` 全部"拒绝访问"，虚拟机内存总量也读不到。
**解决**：改用不依赖 WMI 的方式（`Get-Counter '\Memory\Available MBytes'` 读内存、`[System.IO.DriveInfo]` 读磁盘），并在获得完整权限后继续。

### 0.2 确认 NAT 网段（🔑 极易搞错的点）

**操作：**
```powershell
Get-Content 'C:\ProgramData\VMware\vmnetdhcp.conf' | Select-String 'subnet|fixed-address|host VMnet'
```

**实际结果：**
```
subnet 192.168.10.0 netmask 255.255.255.0 { range 192.168.10.128 192.168.10.254; }
host VMnet8 { hardware ethernet 00:50:56:C0:00:08; fixed-address 192.168.10.1; }
```

**🔑 关键结论：**
- NAT 网段是 **192.168.10.0/24**
- **192.168.10.1 = 宿主机虚拟网卡**（Windows 不响应 ICMP，且**不转发外网流量**）
- **192.168.10.2 = VMware NAT 设备**（才是虚拟机真正的默认网关）

> 💡 这是后面第 3 阶段"虚拟机上不了网"的根因，一开始按 .1 配网关踩了大坑。

### 0.4 资源约束核对（🔑 决定克隆方式）

**操作：**
```powershell
[System.IO.DriveInfo]::new('D') | Select @{N='FreeGB';E={[math]::Round($_.AvailableFreeSpace/1GB,1)}}
Get-Counter '\Memory\Available MBytes'
```

**实际结果与决策：**

| 资源 | 实测 | 约束 | 决策 |
| :--- | :--- | :--- | :--- |
| D 盘可用 | **12.1 GB** | 4 台完整克隆需 ~100GB ❌ | **改用 linked 链接克隆** |
| 内存可用 | 4.0 GB（提交 24.7GB） | 4×2GB=8GB 跑不动 ❌ | LB 降 1GB、Web1 1.5GB、Zabbix 2GB |

**⚠️ 阻碍 2：磁盘空间严重不足**
完整克隆 4 台需要约 100GB，而 D 盘仅剩 12.1GB、C 盘剩 6.6GB。
**解决思路对比：**
1. ❌ 删除现有虚拟机（KKali 27.6GB / Windows 10 48.7GB）→ 属用户资产，不能擅自删
2. ✅ **链接克隆（linked clone）**→ 增量盘只有几 MB 起步，随安装增长约 2-4GB/台
3. ✅ 降低各虚拟机内存配额以适配宿主机

## 第 1 阶段：克隆 4 台虚拟机

### 1.1 前置：源虚拟机关机

**操作：**
```powershell
$vmrun = 'D:\Program Files (x86)\VMware\VMware Workstation\vmrun.exe'
& $vmrun list        # 确认没有运行中的 VM
```

### 1.2 执行链接克隆（🔑 核心步骤）

**操作：**
```powershell
$vmrun = 'D:\Program Files (x86)\VMware\VMware Workstation\vmrun.exe'
$src   = 'D:\Virtual Machines\RHEL10\Red Hat Enterprise Linux 10 64 位.vmx'

foreach ($t in @(
  @{D='D:\Virtual Machines\LB-Master'; V='LB-Master.vmx'},
  @{D='D:\Virtual Machines\LB-Backup'; V='LB-Backup.vmx'},
  @{D='D:\Virtual Machines\Web1';      V='Web1.vmx'},
  @{D='D:\Virtual Machines\Zabbix';    V='Zabbix.vmx'}
)) {
  New-Item -ItemType Directory -Force -Path $t.D | Out-Null
  & $vmrun clone $src "$($t.D)\$($t.V)" linked
}
```

**实际结果：** 4 次 `exit=0` 全部成功；D 盘空间反而从 12.1GB 升到 **14.09GB**（源 VM 关机释放了 2GB 的 .vmem 内存镜像文件）。
每台克隆的增量盘（`*-cl1-s00*.vmdk`）仅 **0.5MB × 6 + 0.2MB**，起点极小。

> **链接克隆原理（答辩可用）**：克隆机与源机共享基础磁盘（只读），自己的写操作全部落在增量盘。因此克隆机**不能脱离源机存在**，源机的 vmdk 不可删除/移动。

### 1.3 调整内存配额

**⚠️ 阻碍 3：直接改 vmx 导致虚拟机无法启动**
用 `Set-Content -Encoding UTF8` 修改 vmx 后，`vmrun start` 报错：
```
Error: Cannot open VM: ... 无法读取虚拟机的配置文件
```
**根因排查：**
```powershell
$bytes = [System.IO.File]::ReadAllBytes($vmx)
$bytes[0..3] -join ','      # 输出 239,187,191 = UTF-8 BOM
Get-Content $vmx -TotalCount 1   # 输出 .encoding = "GBK"
```
两个问题叠加：① PowerShell 5.1 的 `-Encoding UTF8` **会写入 BOM**，VMware 解析 vmx 时被 BOM 顶掉；② 源 vmx 本身是 **GBK 编码**（因为路径含中文"Red Hat Enterprise Linux 10 64 位"）。

**✅ 解决办法：按 GBK 编码写回、不带 BOM**
```powershell
$gbk = [System.Text.Encoding]::GetEncoding(936)
$mem = @{ 'LB-Master'='1024'; 'LB-Backup'='1024'; 'Web1'='1536'; 'Zabbix'='2048' }
foreach ($k in $mem.Keys) {
  $vmx  = Get-ChildItem "D:\Virtual Machines\$k" -Filter *.vmx | Select -First 1
  $text = [System.IO.File]::ReadAllText($vmx.FullName, $gbk)
  $text = $text -replace 'memsize = "\d+"',       "memsize = `"$($mem[$k])`""
  $text = $text -replace 'displayName = "[^"]*"', "displayName = `"$k`""
  [System.IO.File]::WriteAllText($vmx.FullName, $text, $gbk)
}
# 验证：首字节应为 46,101,110（".en"）而不是 239,187,191（BOM）
```

**📸 截图点 1-1：** `D:\Virtual Machines` 目录，显示 4 个新克隆目录（LB-Master / LB-Backup / Web1 / Zabbix）。
**📸 截图点 1-2：** 克隆后增量盘文件列表（体现链接克隆的"小体积"）。

## 第 2 阶段：打通远程管理通道（SSH 工具链）

### 2.1 准备 SSH 客户端（Windows 无 sshpass）

**⚠️ 阻碍 4：Windows OpenSSH 不支持非交互式密码登录**
系统只有 `C:\WINDOWS\System32\OpenSSH\ssh.exe`，无法在脚本里传密码（没有 sshpass）。

**✅ 解决：下载 PuTTY 的 plink/pscp**
```powershell
Invoke-WebRequest 'https://the.earth.li/~sgtatham/putty/latest/w64/plink.exe' -OutFile "$tools\plink.exe"
Invoke-WebRequest 'https://the.earth.li/~sgtatham/putty/latest/w64/pscp.exe'  -OutFile "$tools\pscp.exe"
```
- `plink` 执行远程命令、`pscp` 上传/下载文件

### 2.2 获取并固定主机密钥（🔑 安全前提）

**⚠️ 阻碍 5：`-batch` 模式下无法确认主机密钥**
首次连接报 `FATAL ERROR: Cannot confirm a host key in batch mode`，但我需要这个错误来拿指纹。

**✅ 解决：先用 batch 模式"故意失败"拿到指纹，后续用 `-hostkey` 固定**
```powershell
# 第一次：拿到指纹（连接会被放弃，这是预期的）
& $plink -ssh -batch -l root -pw '你的root密码' 192.168.10.10 "hostname"
# 输出：The server's ssh-ed25519 key fingerprint is:
#       ssh-ed25519 255 SHA256:kT9DtYdMZPKcoYaYrvvOYeCiOSWkgjff444MvtD0dcI

# 之后所有连接都带指纹，防中间人
$fp = 'SHA256:kT9DtYdMZPKcoYaYrvvOYeCiOSWkgjff444MvtD0dcI'
& $plink -ssh -batch -hostkey $fp -l root -pw 'root密码' 192.168.10.10 "hostname"
```

### 2.3 取虚拟机 IP

```powershell
& $vmrun getGuestIPAddress 'D:\Virtual Machines\LB-Master\LB-Master.vmx' -wait
# → 192.168.10.10
```

**📸 截图点 2-1：** SSH 成功登录虚拟机的终端画面（`hostname` + `cat /etc/redhat-release`）。

## 第 3 阶段：网络修复（网关与仓库）

### 3.1 首次连通性诊断（🔑 定位"上不了网"）

**操作：**
```bash
# 在虚拟机内
ip route                                  # 看默认路由
cat /etc/resolv.conf                      # 看 DNS
ping -c 2 -W 2 192.168.10.1               # 宿主机网卡
ping -c 2 -W 2 192.168.10.2               # NAT 设备
ping -c 2 -W 2 114.114.114.114            # 外网
```

**实际结果（关键证据）：**
```
default via 192.168.10.1 dev ens160 ...   ← 网关配错了！
192.168.10.1  → 100% packet loss          ← 宿主机网卡不通
192.168.10.2  → 0% packet loss, 0.6ms     ← NAT 设备通
114.114.114.114 → 100% packet loss        ← 自然上不了外网
```

**⚠️ 阻碍 6：默认网关指向 .1，虚拟机彻底无法访问外网**
源镜像（原来是台 DNS 服务器 ns1）配的网关是 192.168.10.1，但那是宿主机虚拟网卡，**不提供 NAT 转发**。

**✅ 解决：网关改为 NAT 设备 .2**
```bash
nmcli con mod ens160 ipv4.method manual \
  ipv4.addresses 192.168.10.10/24 \
  ipv4.gateway 192.168.10.2 \
  ipv4.dns "192.168.10.2 114.114.114.114"
nmcli con up ens160
```

**🔑 现象提醒：** `nmcli con up` 应用新 IP 后 **SSH 连接会中断**（旧 IP 失效），这是正常的——重新连新 IP 即可。脚本化时不要误判为失败。

> 💡 验证外网是否通的正确方法：**不要只 ping**（NAT 会屏蔽 ICMP），用 `curl -I https://cdn.redhat.com` 或 `dnf repolist` 看 TCP 层是否通。

### 3.2 禁用源镜像残留的失效仓库

**⚠️ 阻碍 7：dnf 卡死 2 分钟以上**
源镜像里配了 `nodesource-nodejs` / `nodesource-nsolid`（Node.js 第三方源），域名 `rpm.nodesource.com` 不可达，每次 dnf 都要等它超时重试：
```
Curl error (6): Could not resolve host: rpm.nodesource.com
错误：为仓库 'nodesource-nodejs' 下载元数据失败
```

**✅ 解决：禁用这两个仓库（写进基础脚本，每台都执行）**
```bash
dnf config-manager --set-disabled nodesource-nodejs nodesource-nsolid 2>/dev/null \
  || sed -i 's/^enabled=1/enabled=0/' /etc/yum.repos.d/nodesource*.repo
```

## 第 4 阶段：红帽订阅重新注册（每台必做）

### 4.1 问题定位（🔑 本毕设最深的坑）

**操作与结果：**
```bash
subscription-manager status          # → 总体状态：已注册
dnf repolist                         # → 已注册但装包失败
dnf install -y nginx keepalived
# → Status code: 403 for https://cdn.redhat.com/.../repomd.xml

subscription-manager refresh
# → 单元 95dc4cfb-... 已被删除 （HTTP 错误码 410 ：Gone）

ls /etc/pki/entitlement/
# → 161253882143565819-key.pem / 161253882143565819.pem   （证书存在但已成"孤儿"）
```

**根因结论：**
- 源镜像的注册单元在**红帽服务器端已被删除**（410 Gone），本地却仍显示"已注册"
- 权益证书失配 → cdn.redhat.com 返回 **403**
- **所有克隆机都继承了这份失效注册**，因此每台都必须重新注册

### 4.2 重新注册（🔑 每台克隆都要做一次）

**⚠️ 阻碍 8：RHEL 10 移除了 `--auto-attach` 参数**
```bash
subscription-manager register --username 账号 --password 密码 --auto-attach
# → subscription-manager: 错误: 无此选项：--auto-attach
```

**✅ 正确命令（RHEL 10）：**
```bash
# 1) 先清掉本地的失效注册
subscription-manager unregister

# 2) 重新注册（不要加 --auto-attach）
subscription-manager register --username 'yyyb_hrbust' --password '你的密码'

# 3) 验证
subscription-manager status          # → 总体状态：已注册
dnf repolist                         # → BaseOS / AppStream 已启用
```

**实际结果：** 4 台分别注册成功，系统名自动取为各自主机名：

| 主机 | 注册系统 ID |
| :--- | :--- |
| lb-master | 86eb1065-5dc2-44a9-8f91-86d7d352d770 |
| lb-backup | 02a798c6-ebf2-4103-ad5d-7c91d173bc62 |
| web1 | 00fc8a04-4a7f-4f25-b68b-daa957e3b50d |
| zabbix | d5ae4bca-d705-4d83-897b-bfc22aa18d3a |

> 💡 组织开启了 **Simple Content Access (SCA)** 时，注册后仓库自动启用，无需再 `attach`。
> 📸 **截图点 4-1：** `subscription-manager status` 显示"已注册" + `dnf repolist` 显示 BaseOS/AppStream（证明使用正版订阅）。

## 第 5 阶段：逐台基础配置

> 由于源镜像带静态 IP 192.168.10.10，**所有克隆机开机时都是同一个 IP**，因此必须**一次只开一台**，改完 IP 再开下一台。

### 5.1 串行操作节奏（🔑 强烈建议照做）

```
开机 LB-Master → SSH .10 → 改主机名/IP(.10) → 部署角色 → 关机
开机 LB-Backup → SSH .10 → 改主机名/IP(.20) → 部署角色 → 关机
开机 Web1      → SSH .10 → 改主机名/IP(.101) → 部署角色
开机 Zabbix    → SSH .10 → 改主机名/IP(.200) → 部署角色
最后全部开机 → 联调
```

### 5.2 基础配置脚本 `base.sh`

**内容：**
```bash
#!/bin/bash
# 用法: bash base.sh <hostname> <ip>
set -e
HOST=$1; IP=$2; GW=192.168.10.2      # 🔑 NAT 网关必须是 .2

# 1) 主机名
hostnamectl set-hostname "$HOST"

# 2) 禁用失效仓库
dnf config-manager --set-disabled nodesource-nodejs nodesource-nsolid 2>/dev/null || \
  sed -i 's/^enabled=1/enabled=0/' /etc/yum.repos.d/nodesource*.repo 2>/dev/null || true

# 3) 静态 IP
IF=$(ip -o link show | awk -F': ' '{print $2}' | grep -Ev '^(lo|virbr)' | head -1)
CONN=$(nmcli -t -f NAME,DEVICE con show | grep ":$IF" | head -1 | cut -d: -f1)
nmcli con mod "$CONN" ipv4.method manual ipv4.addresses "$IP/24" \
  ipv4.gateway "$GW" ipv4.dns "$GW 114.114.114.114"
nmcli con up "$CONN" || true
ping -c 2 -W 3 "$GW" >/dev/null 2>&1 && echo "GW_OK" || echo "GW_WARN"

# 4) SELinux permissive（毕设环境）
setenforce 0 || true
sed -i 's/^SELINUX=.*/SELINUX=permissive/' /etc/selinux/config

# 5) 防火墙：保持开启，精确放行
systemctl enable --now firewalld
firewall-cmd --permanent --add-service=http
firewall-cmd --permanent --add-port=10050/tcp
firewall-cmd --permanent --add-rich-rule='rule protocol value="vrrp" accept'
firewall-cmd --reload

# 6) 时区与基础工具（cronie 提供 crontab）
timedatectl set-timezone Asia/Shanghai
dnf install -y chrony vim wget tar rsync net-tools cronie >/dev/null 2>&1 || true
systemctl enable --now chronyd crond

echo "BASE_DONE $HOST $IP"
```

**各机执行：**
```bash
bash /tmp/base.sh lb-master 192.168.10.10
bash /tmp/base.sh lb-backup 192.168.10.20
bash /tmp/base.sh web1      192.168.10.101
bash /tmp/base.sh zabbix    192.168.10.200
```

### 5.3 上传脚本的标准动作（🔑 常用套路）

```powershell
$pscp = '...\tools\pscp.exe'; $plink = '...\tools\plink.exe'
$fp = 'SHA256:kT9DtYdMZPKcoYaYrvvOYeCiOSWkgjff444MvtD0dcI'; $pw = 'root密码'

# 上传（可一次传多个文件）
& $pscp -batch -hostkey $fp -pw $pw "$sdir\base.sh" "$sdir\lb.sh" root@192.168.10.10:/tmp/
# 执行前务必去掉 Windows 换行（否则 bash 报错）
& $plink -ssh -batch -hostkey $fp -l root -pw $pw 192.168.10.10 "sed -i 's/\r$//' /tmp/*.sh; bash /tmp/base.sh lb-master 192.168.10.10"
```

**⚠️ 阻碍 9：PowerShell + plink 内联引号地狱**
把带 `$(...)`、嵌套引号的复杂命令直接塞进 plink 字符串，会被 **PowerShell 先行解析**，报 `Missing argument in parameter list`、`head : 无法识别`、`无效的后向引用` 等一堆错误。
**✅ 铁律：复杂命令一律写成 `.sh` 文件 → pscp 上传 → plink 执行文件**。这条经验能省掉后面 80% 的调试时间。

### 12.1 为什么不能直接"截虚拟机的屏"

```powershell
# 试过：VMware 自带的截屏命令
& $vmrun -T ws -gu root -gp $pw captureScreen "D:\Virtual Machines\RHEL10-lb-master\..." "shot.png"
# 结果：命令成功执行，但 PNG 只有 69 字节（全黑空图）
```

**原因：** RHEL 10 装的是**文本控制台**（没装图形界面），VMware 抓到的是一块空帧缓冲，没有任何像素内容。
**结论：** 放弃"截虚拟机画面"，改走 **"先用 SSH 采真实输出 → 再渲染成终端窗口"** 的路线。

### 12.2 第一步：用 SSH 采集真实命令输出

工具链：`plink.exe`（明文密码 + `-hostkey` 固定指纹，防中间人）。

```powershell
# 核心函数：在某台虚拟机上执行一条命令，把原始输出存成 txt
function Shot($name, $vhost, $cmd) {
    & $plink -batch -hostkey $fp -pw $pw "root@$vhost" $cmd *> "$src\$name.txt"
}

Shot '06-3_keepalived_conf' '192.168.10.10' 'cat /etc/keepalived/keepalived.conf'
Shot '10-2b_vip_master_down' '192.168.10.20' "echo '...'; hostname; ip addr show ens160 | grep 'inet '; systemctl is-active keepalived"
Shot '10-8_ab_result'       '192.168.10.10' 'cat /tmp/ab_result.txt'
```

这样采到的每一个数字都是**真实环境的真实结果**（真实 IP、真实时间戳、真实压测数据），而不是"照着编一个好看的数字"。

**⚠️ 阻碍 26：PowerShell 里函数参数不能叫 `$host`**
`$host` 是 PowerShell 的**只读自动变量**，用作函数参数会被忽略/报错 → 参数统一改名为 `$vhost`。
**⚠️ 阻碍 27：plink 内联命令里的引号被 PowerShell 抢先解析**
`mysql -e "SELECT ..."` 里的双引号、`$()` 会先被 PowerShell 吃掉，导致 SQL 残片、命令错位。
**✅ 解决：SQL 一律用单引号包裹，复杂逻辑一律写成 .sh 文件上传执行。**

### 12.3 第二步：用 Pillow 把输出渲染成"终端窗口"

```python
# make_terminal_shots.py 核心逻辑

draw.rectangle(...)                                    # 标题栏 + 三个圆点（红黄绿）
```

**⚠️ 阻碍 28：中文全渲染成 □ 方框**

其他细节：
- 窗口宽度按最长行自适应（限制在 860～1500 px），高度按行数累加；
- 超长行 `truncate()` 截断，避免画布撑爆；
- `$` 提示符染成绿色，与真实终端观感一致。

## 附录 C：RHEL 10 与 CentOS 7 差异对照

| 项目 | CentOS 7（原始方案） | RHEL 10（本方案实测） |
| :--- | :--- | :--- |
| 包管理 | yum | **dnf**（yum 为兼容别名） |
| 软件源 | 免费公开源 | **需红帽订阅**（开发者订阅免费，克隆机需逐台重新注册） |
| 注册命令 | `register --auto-attach` | **已移除 `--auto-attach`**，SCA 下注册即启用仓库 |
| 防火墙 | 建议关闭 | **保持开启**，按端口精确放行（80/10050/10051/VRRP） |
| SELinux | 关闭 | **permissive**（生产应 enforcing） |
| 网卡命名 | eth0/ens33 | **ens160**（用 `ip addr` 确认） |
| Zabbix 版本 | 5.0 LTS + httpd | **7.0 LTS + nginx/php-fpm** |
| Zabbix 初始化 | `/usr/share/doc/zabbix-sql-scripts/...` | `/usr/share/zabbix-sql-scripts/mysql/server.sql.gz`（需单独装包） |
| Zabbix 前端 | `http://IP/zabbix` | **`http://IP/`（根路径）** |

## 结语：答辩时可以这样讲

> 我在 VMware 上用 **RHEL 10** 搭建了一套中小企业高可用 Web 运维架构：两台 Nginx + Keepalived 做主备负载均衡，通过 **VRRP 协议**实现 VIP 秒级漂移；一台 Web 业务服务器跑 Nginx + PHP + MariaDB；一台 Zabbix 7.0 监控中心，用**自定义 UserParameter** 监控 Nginx 端口存活，配合阈值触发器和企业微信机器人做告警；备份用 Shell + Crontab + Rsync 实现本地打包、远程同步、7 天保留，并做了**删站恢复演练**验证 RPO。
>
> 实测：VIP 切换约 5 秒、业务不中断；压测 2000 请求 0 失败、1558 req/s；灾难恢复演练从 403 恢复到 200。
>
> 过程中我踩过并解决了：链接克隆的磁盘规划、GBK 编码的 vmx 修复、NAT 网关 .1/.2 的区别、RHEL 订阅 410/403 的重新注册、Zabbix 7.4 无 el10 源的版本回退、以及 SELinux/防火墙的配置取舍——这些真实的排障经历，比"照着教程装一遍"更能体现运维能力。
>
